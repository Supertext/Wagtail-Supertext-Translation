# Changelog

All notable changes to this project are documented here.

## Unreleased

- Added: **Export for translation (XLIFF 1.2 or HTML) and import of translated files**; Supertext SDK 0.5.0. *Settings → Translation files* downloads the texts of a wagtail-localize translation that still need translating as an XLIFF file (one or more languages, for translation tools) or an HTML file (one language, e.g. for Supertext's web app), and imports the translated file into the translation like a machine translation (existing translations never overwritten; texts whose source changed since the export only with *Also import texts whose source changed since the export*), with a summary per page and language; review and publish in the translation editor as usual. Different from wagtail-localize's PO files. Open to editors for the translations they may edit; files up to 10 MB, nothing stored on the server. In English, German, French and Italian.
- Added: **Settings → Supertext → Languages**: a drop-down per locale with Supertext's languages (and the tone where the language offers it), saved in the database (new table; run `python manage.py migrate`). The suggested language is preselected. The `LANGUAGES` option stays as an override for automated setups and wins per locale, so existing configurations keep working unchanged.
- Changed: locales without a chosen language now use an obvious default (`de` → `de-DE`, `en` → `en-US`, `fr` → `fr-FR`, `it` → `it-IT`, `pt` → `pt-PT`, `zh-cn` → `zh-Hans`, `zh-tw` → `zh-Hant`, `es-es` → `es`, …) instead of failing; only locales without one (`en-ie`, `de-li`, `gsw`, …) still need a choice. The *no Supertext language yet* message points to *Settings → Supertext → Languages*. Bundled Supertext SDK updated to 0.4.0 (commit `6aaad33`).
- Changed: version reports, the API key check result and the reachability ping now use Supertext Plugin Health 0.1.0 (bundled in `wagtail_supertext/_vendor/plugin_health`); bundled Supertext SDK updated to 0.3.0 (commit `f7bd414`). No change for sites: settings and stored state stay as they are.
- Added: support for Python 3.14 (tested in CI with Wagtail 8.0 and Django 6.1).
- Added: **Send version information to Supertext** (on by default; `"VERSION_REPORTS": False` or `SUPERTEXT_VERSION_REPORTS=0` turns it off). The plugin reports the site URL and the plugin, Wagtail, Python and SDK versions, whether a key is set and the API key check to the Supertext Commando Center after an update and when the key changes, in the background. No content, no API key, no personal data. See the installation guide.
- Added: automatic **API key check** (Supertext's cost-free `features` call) when the key changes, on *Test connection*, with `supertext_check` and when a translation is rejected; *Settings → Supertext* shows the latest result with its time (with the account and API key links when the key is rejected or missing). *Test connection* now shows this check.
- Added: public ping endpoint `GET /supertext/ping` (add `path("supertext/", include("wagtail_supertext.urls"))` to your `urls.py`), so Supertext can see the site is reachable; 404 while version information is off.
- Added: the plugin's own table (run `python manage.py migrate`) for the reporter's state and the latest key check (never the key).
- Changed: **languages are no longer guessed.** A Wagtail locale whose code is a Supertext code (`de-ch` → `de-CH`, `fr-ch`, `es`, `zh-hans`, apart from case and `_`/`-`) is used as it is; every other locale needs `LANGUAGES` → `code` (its meaning changed: it is now the mapping, without default regions). The default regions are gone: they were wrong for most languages (Supertext wants `es`, `sl`, `nl` without region and `zh-Hans` instead of `zh-CN`). An unmapped locale gets the message *has no Supertext language yet* (four languages) and nothing is sent for it; *Settings → Supertext* marks it *Not mapped*.
- Changed: formal/informal is only sent where Supertext offers it; for English, Swiss German, Romansh, Albanian and Serbian a set `politeness` gives the message *Supertext offers no formal or informal tone for this language* instead of a failed request, and *Settings → Supertext* warns.
- Fixed: bundled Supertext SDK 0.2.1 (commit `eeba8fa`): one `LANGUAGES` → `code` entry serves both directions; a mapped language is sent as the source in its source form (`de-CH` → `de`), so English as the source no longer fails with an `en-US` mapping.
- Changed: bundled Supertext SDK 0.2.0 (commit `c66cb4d`, `v1` namespace) with the key check, the version reports and the API's language list; `scripts/vendor-sdk.sh` copies its subpackages.
- Changed: the connection to Supertext now uses the shared [Supertext SDK](https://github.com/Supertext/Supertext-API-SDK-and-Guide) (Python SDK, shipped inside the package, so nothing else needs installing), still through `requests`. Translation works as before; an unsupported language pair now has its own message (*Supertext does not support this language pair*) in English, German, French and Italian. The package no longer needs BeautifulSoup. An unknown language (e.g. `xx-YY`) is now reported as an unsupported language pair too, not as "resource not found" (Supertext answers it with HTTP 404).
- Added: French and Italian interface (and German where it was missing): *Settings → Supertext* and all Supertext error messages follow the user's admin language.
- The "No Supertext API key" and "Authentication failed" messages now also link to Supertext account signup.
- *Settings → Supertext* shows the plugin version, linked to its release notes on GitHub.

## 0.1.0 — 2026-10-07

- *Settings → Supertext*, the "No Supertext API key" and "Authentication failed" messages, the installation guide and the README now link to Supertext account signup and API key generation (supertext.com → Integrations → API, Admin role required).
- First version: `wagtail_supertext.SupertextTranslator`, a wagtail-localize machine translator using the Supertext AI file translation API (Wagtail 7.0+, wagtail-localize 1.12+). Editors use wagtail-localize's **Translate with Supertext** button.
- All missing strings of a page go to Supertext as one document per language; each string (a whole paragraph with its inline formatting and links) is one unit, so sentences translate as a whole.
- Page slugs are translated as words and turned back into slugs.
- Options: `API_KEY` (with or without the `Supertext-Auth-Key` prefix; `SUPERTEXT_API_KEY` wins), `ENVIRONMENT`, `ENDPOINT` (`SUPERTEXT_API_ENDPOINT` wins), `LANGUAGES` (Supertext code and tone per locale), `TIMEOUT`, `POLL_INTERVAL`.
- Requests that hit Supertext's per-second rate limit are retried automatically.
- *Settings → Supertext* admin page (configuration, *Test connection*) and `manage.py supertext_check`; admin strings in English and German.
- Demo for Railway (`demo/`): Wagtail 8 on PostgreSQL with German, French and Italian (Switzerland), a sample page, and `DEMO_ADMIN_*` / `DEMO_EDITOR_*` accounts created on every start.
- Docs with screenshots, regenerated by `tests/docs/screenshots.mjs` against a stand-in API.
